# 推荐系统数据集目录与选型指南

本目录不只关注“有没有用户—物品交互”，还关注学生能否看见和理解被推荐的对象。

推荐系统数据通常由两部分组成：

```text
用户行为：谁在什么时间看过、点击过、收藏过、购买过什么
物品内容：这个商品/新闻/电影/书/菜谱到底是什么
```

理想的数据集同时提供这两部分；如果只有 ID，也应该能通过官方元数据或详情链接还原物品的真实含义。

## 一览表

| 数据集 | 推荐对象 | 行为数据 | 可见内容 | 难度 | 课程建议 |
|---|---|---|---|---|---|
| MovieLens | 电影 | 评分、标签 | 片名、类型、外部链接 | 入门 | 第一份作业 |
| Goodbooks-10k | 图书 | 评分、想读 | 书名、作者、年份、标签、详情链接 | 入门/进阶 | 内容增强推荐 |
| Amazon Reviews | 商品 | 评分、评论、时间 | 标题、价格、品牌、类别、图片/关联商品 | 进阶 | 商品和文本推荐 |
| Yelp | 餐厅/商户 | 评分、评论、签到 | 名称、类别、城市、位置、营业属性 | 进阶 | 地理和场景推荐 |
| MIND | 新闻 | 点击历史、曝光 | 标题、摘要、类别、URL、实体 | 进阶 | 新闻和序列推荐 |
| Food.com | 菜谱 | 评分、评论、收藏/互动 | 菜名、配料、步骤、类别、图片/营养信息 | 进阶 | 生活场景推荐 |
| Steam | 游戏 | 推荐/不推荐评论、游戏行为 | 游戏名称、标签、简介、评价、商店页 | 进阶 | 游戏和文本推荐 |
| RetailRocket | 电商商品 | 浏览、加购、购买 | 商品属性、类别树；部分字段匿名 | 挑战 | 行为预测和召回排序 |

## 1. MovieLens：最适合入门

- 官方入口：<https://grouplens.org/datasets/movielens/>
- 推荐对象：电影
- 行为：用户评分、标签
- 内容：电影标题、类型、外部链接
- 推荐任务：UserCF、ItemCF、矩阵分解、评分预测、Top-N
- 推荐版本：MovieLens 100K 或 1M

MovieLens 的交互数据比较干净，适合第一次讲清楚用户、物品、评分矩阵和时间切分。它的内容信息相对简单，但电影标题和类型足以让学生理解推荐结果。

展示建议：

- 推荐列表显示电影名和类型，不要只显示 `movie_id`
- 将 `movies.csv` 与 `ratings.csv` 连接
- 可以使用 `links.csv` 中的外部 ID 访问电影详情，但不要批量抓取第三方页面

## 2. Goodbooks-10k：直观的图书推荐

- 项目页：<https://github.com/zygmuntz/goodbooks-10k>
- 推荐对象：图书
- 行为：评分、标记为“想读”
- 内容：书名、作者、出版年份、平均分、标签/书架
- 推荐任务：协同过滤、内容推荐、混合推荐、冷启动
- 规模：约 1 万本书、约 600 万条评分

这个数据集比 MovieLens 更适合做可视化：学生可以在推荐列表里展示书名、作者、标签和平均评分。数据中的 Goodreads ID 还可以帮助定位书籍详情，但使用外部页面或封面时要遵守相应条款。

## 3. Amazon Reviews：商品、评论和元数据

- 官方入口：<https://mcauleylab.ucsd.edu/public_datasets/data/amazon/datasets.html>
- 推荐对象：商品
- 行为：评分、评论、时间、帮助票
- 内容：商品标题、价格、品牌、类别、图片 URL、关联商品
- 推荐任务：商品推荐、文本增强、冷启动、关联商品推荐
- 建议：先选一个类别，例如 Books、Electronics 或 Video Games

Amazon 数据内容丰富，但规模很大。课堂上不建议直接使用全量数据，可以选择一个类别或 5-core 子集。

展示建议：

- 交互表负责回答“用户喜欢什么”
- 商品元数据负责回答“这个商品是什么”
- 推荐结果至少显示商品标题、类别和评分
- 如果显示图片，优先使用数据集提供的链接或经过许可的缩略图
- 不要把原始评论大文件或图片批量提交到 GitHub

## 4. Yelp：餐厅和本地生活推荐

- 数据入口：<https://business.yelp.com/data/resources/open-dataset/>
- 推荐对象：餐厅、商户
- 行为：评分、评论、签到
- 内容：商户名称、类别、城市、经纬度、营业时间和属性
- 推荐任务：餐厅推荐、地理位置推荐、评论文本、多样性和长尾分析

Yelp 的优势是场景非常直观：学生能理解“给某个用户推荐附近的餐厅”。经纬度和商户类别也适合扩展地理距离、区域偏好和多样性指标。

注意：下载和使用前要阅读当前官方数据条款。文档中的示例字段不等于可以自由抓取或重新发布 Yelp 页面内容。

## 5. MIND：新闻点击和用户兴趣

- 官方介绍：<https://www.microsoft.com/en-us/research/publication/mind-a-large-scale-dataset-for-news-recommendation/>
- 项目与评测代码：<https://github.com/msnews/MIND>
- 推荐对象：新闻
- 行为：曝光、点击历史、点击/未点击标签
- 内容：标题、摘要、类别、子类别、URL、实体
- 推荐任务：新闻推荐、序列推荐、CTR 预测、用户兴趣建模

MIND 解决了“只有新闻 ID，看不到新闻内容”的问题。学生可以直接展示标题、摘要和新闻类别，观察模型推荐的主题是否合理。

展示建议：

- 将 `behaviors.tsv` 中的新闻 ID 连接到 `news.tsv`
- 用户历史显示为“新闻标题序列”，不要只显示 `N123`
- 推荐页面可以同时显示新闻标题、类别和摘要
- 需要注意新闻数据的时间顺序，不能用未来新闻内容泄漏到训练阶段

## 6. Food.com：可以看懂的菜谱推荐

- 网站背景：<https://www.food.com/how-to/about-us-31>
- 推荐对象：菜谱
- 行为：评分、评论、收藏或其他互动
- 内容：菜名、配料、烹饪步骤、类别、营养信息、图片
- 推荐任务：菜谱推荐、基于配料的内容推荐、饮食偏好和冷启动

菜谱是很适合课堂展示的推荐对象：学生可以看到推荐的菜名、配料和评分，并且容易设计“相似菜谱”“低卡推荐”“缺少某种食材时的推荐”等任务。

使用前应确认数据文件的来源和许可。图片通常比文本更敏感，课程仓库建议只保存少量获许可的样例或图片链接。

## 7. Steam：游戏内容和用户评价

- Steam 官方评论接口说明：<https://partner.steamgames.com/doc/store/getreviews>
- 推荐对象：电子游戏
- 行为：推荐/不推荐评论、拥有和游玩行为（视数据版本而定）
- 内容：游戏名称、简介、标签、开发商、评价和商店页面
- 推荐任务：游戏推荐、文本分类、标签推荐、相似游戏和冷启动

游戏推荐很容易做出有感觉的结果：学生可以展示游戏封面、标签、简介和评价文本。不过不同 Steam 数据集的授权和字段差异较大，建议选定一个有清晰许可说明的版本，不要默认从 Steam 页面批量爬取。

## 8. RetailRocket：接近真实业务的电商行为

- 数据入口：<https://www.kaggle.com/datasets/retailrocket/ecommerce-dataset>
- 推荐对象：电商商品
- 行为：浏览、加购物车、购买
- 内容：商品属性和类别树；部分属性为匿名字段
- 推荐任务：下一次行为预测、召回、排序、会话推荐、冷启动
- 难度：挑战

RetailRocket 的特点不是内容最丰富，而是行为链条更接近真实电商：

```text
浏览 → 加购物车 → 购买
```

它适合让学生理解隐式反馈：一次购买通常比一次浏览更强，但浏览数量更多。缺点是商品属性中存在匿名字段，展示效果不如 Amazon、Food.com 或 MIND 直观。

## 选型建议

### 第一次做推荐系统

选择：

1. MovieLens 100K
2. Goodbooks-10k 的小样本
3. 一个带标题和类别的 Amazon 子集

重点学习：

- 用户—物品交互矩阵
- 协同过滤
- 时间切分
- Top-K 评测
- 将 ID 连接到可读的物品信息

### 想做“看得见”的推荐页面

优先选择：

1. Goodbooks-10k
2. MIND
3. Food.com
4. Amazon Reviews
5. Yelp

推荐结果至少显示：

- 对象名称
- 类别或标签
- 一句描述或摘要
- 评分或热度
- 可选的合法图片/详情链接

### 想研究真实业务行为

选择：

1. RetailRocket
2. MIND
3. Amazon Reviews
4. Yelp

重点研究：

- 隐式反馈
- 曝光偏差
- 点击与购买的差异
- 长尾商品
- 冷启动
- 召回与排序

## 统一的数据展示规范

无论数据集的原始格式是什么，建议在课程项目中统一转换为两张表：

### interactions.csv

| user_id | item_id | event_type | value | timestamp |
|---|---|---|---:|---:|
| U001 | I101 | rating | 5 | 2024-01-01 |
| U001 | I203 | click | 1 | 2024-01-02 |

### items.csv

| item_id | title | category | description | image_or_url |
|---|---|---|---|---|
| I101 | 示例商品 | Books | 示例描述 | 官方链接 |

这样学生既可以使用统一的推荐算法代码，也可以在展示层看到真实的推荐对象。

## 使用和版权原则

- 原始数据不要直接提交到公开 GitHub 仓库
- 记录数据集版本、下载日期和许可
- 不要把密码、Token、Cookie 或个人数据提交到仓库
- 图片优先使用官方允许的链接或自行制作的占位图
- 如果数据集只能提供 ID，就把 ID 与公开元数据表连接，而不是擅自抓取网页
- 课程报告中注明数据集来源和引用方式
